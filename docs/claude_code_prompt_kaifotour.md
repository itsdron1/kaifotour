# Промт для Claude Code: сайт KAIFO (редакционный стиль)

> Как использовать: создай пустой репозиторий/папку проекта, положи туда три файла-приложения ниже (раздел «Файлы-приложения») в подпапку `docs/`, затем открой Claude Code в этой папке и вставь текст из раздела «Промт для вставки в Claude Code» первым сообщением. Claude Code сам прочитает `docs/*.md`, спланирует работу и напишет код — в отличие от Cursor, ему не нужно скармливать спецификацию по кускам вручную.

---

## Файлы-приложения (положить в `docs/` перед стартом)

Скопируй в проект как есть, под этими именами:

- `docs/tz-main.md` ← содержимое файла `cursor_prompt_kaifotour.md` (структура сайта, контакты, базовая палитра Deep Ocean & Brass, техтребования к CTA)
- `docs/new-tours-content.md` ← содержимое файла `kaifotour_new_tours_content.md` (тексты 7 новых туров категории Day Tours + 2 расширения существующих категорий)
- `docs/editorial-style.md` ← содержимое файла `cursor_prompt_kaifotour_editorial_style.md` (редакционное арт-направление: типографика, композиция секций, структура коллажей)

Эти три файла — источник истины по контенту и брендингу. Промт ниже — это только порядок работы и технические решения для Claude Code, он не дублирует контент из них.

---

## Промт для вставки в Claude Code

```
Роль: ты — senior frontend-разработчик. Нужно с нуля построить маркетинговый
сайт для бренда KAIFO (туры и прокат снаряжения для активностей на
Бали: лодки, серфинг, снорклинг, ATV, эндуро, джип, джетски, Harley).

Прежде чем писать код — прочитай полностью три файла в docs/:
1. docs/tz-main.md — базовая структура сайта, контакты, палитра, CTA
2. docs/new-tours-content.md — тексты новых туров (Day Tours) и расширений
   существующих категорий
3. docs/editorial-style.md — арт-направление: редакционная типографика
   (курсивный serif + Barlow), композиция секций, приём "карточки-открытки"

Собери из всех трёх файлов единую картину сайта: структура и палитра берутся
из tz-main.md, визуальная подача секций — из editorial-style.md (он
переопределяет некоторые названия и композицию секций из tz-main.md — там,
где они расходятся, приоритет у editorial-style.md), контент новых туров —
из new-tours-content.md. Если что-то в файлах противоречит друг другу —
останови работу и спроси меня, а не выбирай самостоятельно.

Технический стек (зафиксирован, не выбирай другой):
- Next.js 14+ (App Router) + TypeScript
- Tailwind CSS — все цвета и шрифты вынести в tailwind.config как токены
  дизайн-системы (см. палитру Deep Ocean & Brass в docs/tz-main.md), не
  хардкодить hex-коды по компонентам
- Framer Motion (или CSS-анимации, если не хочешь тянуть зависимость) —
  для плавных scroll-эффектов из editorial-style.md
- Контент туров (все 17: 10 текущих категорий + 7 Day Tours) вынести в
  типизированный дата-файл `data/tours.ts` (title, slug, category, kicker,
  durationLabel, priceFromIDR, includes: string[], difficulty, badge,
  ctaWhatsappText) — секции и страницы туров рендерятся из этого файла,
  а не хардкодятся по одному в JSX
- Каждый тур — отдельная страница по маршруту `/tours/[slug]`, генерируемая
  из data/tours.ts (не создавай 17 одинаковых файлов вручную)

Порядок работы — веди явный todo-лист (используй свой планировщик задач) и
проходи по нему пунктами:

1. Инициализация проекта, Tailwind, шрифты (Barlow, Barlow Condensed,
   Playfair Display italic — импорт см. в docs/editorial-style.md),
   design-токены в tailwind.config
2. data/tours.ts — все 17 туров с полями выше, включая пометку
   isMultiDay: true и published: false для Nusa Lembongan и Sumba (они не
   должны рендериться в каталоге, пока я явно не подтвержу — см.
   ограничение в new-tours-content.md, Блок C)
3. Header/nav в редакционном минималистичном стиле
4. Hero-секция
5. Секция "How We Ride & Explore" (4 категории на фотоколлаже)
6. Основной каталог — рендер из data/tours.ts, с фильтрами; секция подачи —
   "Tours Worth Riding" (тёмный фон, нумерованный список + карточки-открытки)
7. Страница отдельного тура (шаблон, используется для всех 17)
8. Секция "Beyond the Booking / Into the Moment" (плейсхолдеры статистики и
   заготовка карточки истории — без выдуманных отзывов)
9. Секция "Plan Your Bali Trip" — форма собирает поля и на submit формирует
   ссылку https://wa.me/6285190101270?text=... с урл-энкодингом введённых
   данных (name, dates, tour type), открывает в новой вкладке; бэкенд не
   нужен
10. Footer, юридические ссылки-заглушки, FAQ-секция (вопросы — см.
    tz-main.md, раздел FAQ)
11. Адаптивная вёрстка 375/768/1024/1440 — на мобильном коллажи и
    "раскиданные" карточки превращаются в вертикальный стек
12. SEO: мета-теги, Open Graph, alt-тексты, sitemap.xml, robots.txt

После каждого крупного пункта — запусти `npm run dev`, убедись, что страница
рендерится без ошибок в консоли, и переходи к следующему. В конце — прогони
`npm run build` и `npm run lint`, исправь все ошибки и warnings перед сдачей.

Жёсткие ограничения (см. также docs/tz-main.md и docs/new-tours-content.md):
- Никаких текстов/фото/логотипов, скопированных с travel-friends.live или
  из демо-шаблона "WanderLust" (getlayers.ai) — только структурные приёмы,
  контент — свой, из docs/
- Цвет CTA-кнопок — только акцентный `#C0913F`, не стандартный
  WhatsApp-зелёный
- Нигде не использовать чистый белый `#FFFFFF` — фон страницы `#F4F1EB`
- Реальные цифры (число туристов, лет работы, отзывы) — только плейсхолдеры
  вида `[X]`, не выдумывать
- Nusa Lembongan & Ceningan и Sumba — не публиковать в каталоге
  (published: false), см. п.2 выше

Коммить в git после каждого завершённого пункта плана осмысленным
сообщением (conventional commits: feat/fix/style). Не делай один гигантский
коммит в конце.

Когда весь план выполнен — пришли мне итоговое summary: что сделано, какие
решения принял самостоятельно (если пришлось), что осталось на моей
стороне (реальные фото, отзывы, точные цифры статистики, решение по
мультидневным турам Nusa Lembongan/Sumba).
```

## Почему промт для Claude Code отличается от промта для Cursor

- **Файлы вместо вставки текста целиком.** Claude Code сам читает файлы проекта — не нужно пересказывать весь контент в одном сообщении, достаточно сослаться на `docs/*.md` и сказать, что с чем сверять при противоречиях.
- **Зафиксированный стек.** В Cursor-версии стек был «на усмотрение разработчика» — для автономного агента это источник лишних решений и расхождений между запусками, поэтому здесь стек и структура данных (`data/tours.ts`) зафиксированы жёстко.
- **Явный todo-план и точки самопроверки.** Claude Code умеет вести список задач и запускать команды (`npm run dev/build/lint`) — промт явно просит это делать после каждого шага, а не просто «сделай всё и покажи в конце», как в чат-ориентированном промте для Cursor.
- **Git-коммиты по шагам.** Это даёт возможность откатиться к любому промежуточному состоянию и явно видит прогресс — не критично в Cursor-чате, но важно при автономной работе агента.
- **Явное указание останавливаться при противоречиях** между тремя референс-файлами — снижает риск, что агент «додумает» за тебя решение по брендингу.
