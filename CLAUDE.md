- **Логотип:** файлы в `public/brand/` — `kaifo-logo.svg` (тёмные буквы, для светлого фона), `kaifo-logo-light.svg` (светлые буквы и волны посветлее, для тёмного #0F2230), те же логотипы в PNG 2400px, `kaifo-icon.svg` (значок вкладки, сам подстраивается под тёмную тему браузера), `kaifo-icon-512.png`, `apple-icon.png` 180×180.
- **Правило фона:** на тёмном — `kaifo-logo-light.svg`, на светлом — `kaifo-logo.svg`. Пропорции 4352 × 1228 (ширина ≈ 3.54 × высоты). Размеры: шапка 36×128 на десктопе и 28×99 на мобильном, футер 44×156. Вставляем через next/image с `unoptimized`, всегда с `width`/`height`, `alt="KAIFO"`, ссылка на главную текущего языка.
- **Логотип не перерисовываем и не перекрашиваем** через CSS (`filter`, `fill`) — только эти файлы. Иконки вкладки и iPhone подключены один раз в `rootMetadata` (`lib/seo.ts`), общий для `app/(en)` и `app/(ru)`.
- **KAIFO в обычном тексте** (заголовки, «Почему KAIFO?», буквы K-A-I-F-O в разделе «О нас», title и описания) остаётся текстом: это смысл и SEO, а не логотип.

## Языки

- Три языка: **EN по умолчанию** в корне (`/`, `/tours`, `/legal/...`), **RU** под `/ru`, **ID** (индонезийский) под `/id`. Язык браузера не определяем.
- **Любой новый текст добавляется сразу на трёх языках.** Тип словаря выведен из английского (`typeof en` в `lib/dictionaries.ts`), поэтому пропущенный ключ в RU или ID валит сборку — это задумано, не обходить.
- Переключатель языка пишет выбор в cookie `NEXT_LOCALE` на год, `middleware.ts` читает её и отдаёт нужную версию при заходе на корень. Внутренние адреса не редиректятся: присланная EN-ссылка открывается на английском.
- Пути собираем через `localizedPath` из `lib/i18n.ts`, языковые префиксы руками не пишем. Маршруты живут в группах `app/(en)`, `app/(ru)`, `app/(id)` — страницы там тонкие обёртки вокруг компонентов из `components/pages`.
- Цены форматирует только `formatIDR` / `formatIDRCompact` из `lib/format.ts`: «from 850K IDR», «от 850K IDR», «mulai Rp850 ribu». В компонентах цену руками не собираем.
- Проверки перевода: `npm run check:en` (нет кириллицы на английских страницах) и `npm run check:id` (нет кириллицы и английских остатков на `/id`). Таблицу для вычитки индонезийского пересобирает `npm run docs:id`.

## SEO

- Адрес сайта — `SITE_URL` в `lib/site.ts` (с www). От него считаются metadataBase, canonical, og:url, sitemap, robots и JSON-LD; адрес без www в коде не пишем. `*.vercel.app` закрыт от индексации заголовком в `next.config.ts`.
- У каждого тура `seoTitle` (тур и место, без цены и бренда — их добавляет `lib/page-metadata.ts`) и `seoDescription` (140–155 знаков, только факты из данных тура) на трёх языках.
- Поля тура `itinerary`, `pickup`, `notIncluded`, `whatToBring`, `faq` заполняются только фактами от заказчика (вопросы — `docs/tour-content-questions.md`); пустое поле — блок не показывается.
- JSON-LD: TravelAgency на главной, TouristTrip + Offer + BreadcrumbList на турах. AggregateRating и Review не добавляем. Проверка — `npm run check:ld` после сборки.
- Неразрывный пробел в данных и словарях пишем явно как ` `, не невидимым символом и не `&nbsp;` (в title он вылез бы текстом). Число с единицей в SEO-текстах склеиваем им же: `3145 м`. `npm run check:meta` после сборки ловит `&nbsp;` в метатегах, неверный og:locale:alternate и почту без `mailto:`.
- Текст страницы не дублируем: декоративные копии текста — псевдоэлементами, обороты карточек туров появляются в DOM только после переворота.
- Число гостей (`site.stats.guests`, сейчас 1000) и часы работы (`site.openingHours`, ежедневно 8:00–20:00 по Бали) — в `lib/site.ts`, только по данным заказчика. Часы показаны в футере и стоят в разметке TravelAgency — менять в одном месте.

## Аналитика

- Vercel Web Analytics в трёх layout. GA4 (`GA_MEASUREMENT_ID` в `lib/site.ts`), Consent Mode v2, баннер cookies и события — `components/analytics/`. Грузятся только на хостах из `ANALYTICS_HOSTS` (боевой домен), на localhost и `*.vercel.app` их нет. Описание и проверка — `docs/analytics.md`.
- GA4 подключён прямым gtag.js. **Если когда-нибудь подключим GTM** (`NEXT_PUBLIC_GTM_ID`), GA4 переносится внутрь GTM, а прямой gtag убирается — `SiteAnalytics` уже переключается сам, вдвоём они не грузятся.
- Порядок во встроенном скрипте `analytics-init` не менять: consent default → сохранённый выбор (cookie `kaifo_consent`, 6 месяцев) → `js` → `config`. События — только через `track()` из `lib/analytics.ts` (`gtag('event')`); `page_view` вручную не шлём.
- Для проверки баннера и событий локально: временно добавить `"localhost"` в `ANALYTICS_HOSTS` и подставить фиктивный ID, чтобы не слать тестовые хиты в настоящий ресурс; после проверки вернуть.
- События ловит один общий обработчик кликов. Для новой кнопки ничего не нужно, кроме `data-placement` (и `data-tour-slug`, если она про тур) на её блоке.

## Видео на первом экране

- Файлы — `public/media/`: `hero.mp4` и `hero-poster.jpg` для компьютеров, `hero-mobile.mp4` и `hero-mobile-poster.jpg` для экранов до 768px. Имена заданы в одном месте, `components/home/HeroMedia.tsx`.
- **При замене видео или постера меняем имя файла** (`hero-v2.mp4`) и обновляем его в `HeroMedia.tsx`: `/media/*` кэшируется браузерами на год как immutable (`next.config.ts`), под старым именем посетители увидят старый файл.
- Постер виден сразу, видео грузится только после события `load` и только одно, под ширину экрана. LCP для Chrome — H1: картинки на весь экран кандидатами не считаются, поэтому `fetchPriority="high"` постеру не ставим (замер: +0,2 с к LCP). При prefers-reduced-motion, saveData и медленной сети (slow-2g, 2g, 3g) видео нет совсем, остаётся постер. Логика — `components/home/HeroVideo.tsx`.

## Анимации

- Кривые, длительности и шаг задержки — в `lib/motion.ts`. Новые анимации берут их оттуда, свои числа не заводим: `EASE_REVEAL` совпадает с `editorial` в `tailwind.config.ts`, поэтому CSS-переходы и motion идут в одном ритме.
- За кадром ничего не анимируем: стопки (`CardStack`) листаются, только пока их видно, круг туров запускает вылет при показе. Постоянный цикл анимации на скрытой секции держал главный поток телефона занятым на 34–60% в простое.
- Фото, которых ещё не видно, не качаем заранее: дальние карточки стопки историй получают фото по признаку `near` из `CardStack`, фото колоды и её фон — через `useDeferredMedia` (первая прокрутка или секунда после `load`).
- У ссылок на туры с карточек `prefetch={false}`: десятки карточек на экране иначе дают десятки запросов страниц.
- Тени карточек — токены `shadow-polaroid` и `shadow-polaroid-lift`, и лежат они на гранях карточки. `filter: drop-shadow` на движущихся элементах не используем: он пересчитывается каждый кадр и роняет плавность круга из 17 карточек.
